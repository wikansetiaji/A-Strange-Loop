# Phase 2: Multi-Session Persistence

## Overview

The app currently supports a single ephemeral chat. Phase 2 adds persistent multi-session support with a sidebar UI, auto-generated titles, search, pin, delete, and brain preview capabilities.

## FirestoreService — New Methods

Based on the existing `FirestoreService` (`lib/services/firestore_service.dart`), these new methods integrate with the existing Firebase setup (already configured with `firebase_core`, `cloud_firestore`, and Firebase Auth).

| Method | Purpose | Firestore Operation |
|---|---|---|
| `createSession(Session)` | Create new session doc | `collection('sessions').doc(id).set(data)` |
| `loadSessions()` | Fetch all session metadata for sidebar | `collection('sessions').orderBy('pinned', descending: true).orderBy('updated_at', descending: true).get()` — returns `List<Session>` |
| `loadMessages(sessionId)` | Fetch messages for a given session | `collection('sessions').doc(sessionId).collection('messages').orderBy('order').get()` — returns `List<Message>` |
| `saveMessage(sessionId, Message)` | Append a message to a session | `collection('sessions').doc(sessionId).collection('messages').add(data)` |
| `updateSessionMeta(sessionId, data)` | Update metadata (title, pinned, last_message, tokens, updated_at) | `collection('sessions').doc(sessionId).set(data, SetOptions(merge: true))` |
| `deleteSession(sessionId)` | Delete session + all messages | Delete messages subcollection recursively, then delete session doc |
| `pinSession(sessionId, bool)` | Toggle pin | `updateSessionMeta(sessionId, {'pinned': pinned, 'updated_at': FieldValue.serverTimestamp()})` |
| `searchSessionsByTitle(query)` | Prefix search on title | `collection('sessions').orderBy('title').startAt([query]).endAt([query + '\uf8ff']).get()` |
| `cleanEmptySession(id)` | Delete session if `message_count == 0` | `deleteSession()` internally |

### Deleting a subcollection recursively

Firestore does not auto-delete subcollections when the parent document is deleted. Implementation:

```dart
Future<void> deleteSession(String sessionId) async {
  final messages = await _firestore
      .collection('sessions').doc(sessionId)
      .collection('messages').get();
  final batch = _firestore.batch();
  for (final doc in messages.docs) {
    batch.delete(doc.reference);
  }
  batch.delete(_firestore.collection('sessions').doc(sessionId));
  await batch.commit();
}
```

## AIService — Title Generation

Add `generateTitle()` to `lib/services/ai_service.dart`:

```dart
Future<String?> generateTitle(String firstUserMsg, String firstAssistantMsg) async {
  // Non-streaming call to DeepSeek API
  // System prompt:
  //   "Generate a short title (max 6 words) for this conversation. Output ONLY the title, no quotes, no punctuation."
  // User prompt:
  //   "User: ${firstUserMsg}\n\nAssistant: ${firstAssistantMsg}"
  // max_tokens: 20, temperature: 0.3, stream: false
  // Returns the title string, or null on failure
}
```

**Timing**: Called asynchronously after the first assistant response is fully received in a new session (session has exactly 2 messages: 1 user + 1 assistant). Non-blocking — the title pops into the sidebar a moment later.

**Fallback**: If the API call fails or returns nothing, title = `"Chat · Mon 3:14 PM"` (formatted `created_at`).

## ChatState Refactor

`lib/providers/chat_state.dart` is currently single-session. It needs to become multi-session aware.

### New state fields

```dart
String currentSessionId;          // Active session (not final, set when switching/creating)
List<Session> sessions = [];       // Sidebar list
bool isLoadingSessions = false;   // Loading state for session list
```

### New methods

| Method | Behavior |
|---|---|
| `loadSessions()` | Fetch session list from Firestore, update `sessions` |
| `createNewSession()` | 1. If current session has `message_count == 0`, call `firestore.cleanEmptySession()`. 2. Generate new `sessionId` (`DateTime.now().millisecondsSinceEpoch.toString()`). 3. Create Firestore doc. 4. Clear local `messages`. 5. Add to `sessions` list. 6. `notifyListeners()` |
| `switchSession(sessionId)` | 1. Save current session state (tokens). 2. Set `currentSessionId`. 3. Load messages from Firestore. 4. Restore `sessionPromptTokens`/`sessionCompletionTokens`/`_conversationSummary`/`_lastSummarizedIndex` |
| `deleteSession(sessionId)` | 1. Remove from Firestore. 2. Remove from local `sessions` list. 3. If it was the current session, switch to the most recent remaining session (or create new). 4. `notifyListeners()` |
| `pinSession(sessionId)` | 1. Toggle `pinned` in Firestore. 2. Update local list. 3. Re-sort `sessions`. 4. `notifyListeners()` |
| `searchSessions(query)` | If query empty → load all sessions. Else → Firestore title search + client-side content filter on already-loaded results |
| `_maybeGenerateTitle()` | **Called after `sendMessage()` completes, when `messages.length == 2` and `currentSession.title == null`.** Fires async: `ai.generateTitle(messages[0].content, messages[1].content)` → update Firestore + local title |

### Modified `sendMessage()`

After the assistant response is saved to `messages`:
1. Call `firestore.saveMessage(sessionId, userMsg)` and `firestore.saveMessage(sessionId, assistantMsg)`
2. Update `firestore.updateSessionMeta()` with last_message, updated_at, message_count, tokens
3. After saving: if this is the first exchange (`messages.length == 2` and title is null), trigger `_maybeGenerateTitle()`

### Session token persistence

Currently, tokens are stored in `sessionPromptTokens`/`sessionCompletionTokens`. These must:
- Be saved to Firestore on every message (in `updateSessionMeta`)
- Be restored when switching sessions (from the `Session` object loaded from Firestore)

### Compression state persistence

`_conversationSummary` and `_lastSummarizedIndex` should also be saved to and loaded from Firestore (as fields on the session document). This allows switching sessions without losing the compressed history.

**New session doc fields**: `conversation_summary` (`String?`), `last_summarized_index` (`int`, default 0).

## App Startup Flow — `main.dart`

1. Initialize Firebase + seed brain (existing)
2. On auth success → `ChatScreen` loads
3. `ChatScreen.initState()` or `ChatState` constructor → calls `loadSessions()`
4. If sessions exist → switch to the most recent one (first in the sorted list)
5. If no sessions → stays on empty state (new chat ready)

## Empty Session Auto-Clean

When `createNewSession()` is called:
1. Check if `currentSessionId` has `message_count == 0` in the local `sessions` list
2. If yes → call `firestore.cleanEmptySession(currentSessionId)` → remove from local `sessions`
3. Generate new session ID and proceed

This prevents accumulating empty sessions from "New Chat" taps without sending a message.

## Implementation Notes

### Lazy Persistence
Sessions are NOT persisted to Firestore until the first message is sent and a response is received. `_persistAfterResponse` calls `set(merge: true)` which creates the Firestore document lazily. Empty sessions (created via "New Chat" but never messaged) never touch Firestore.

### Title Generation
Uses `max_tokens: 256` (up from 20) because DeepSeek v4 Flash is a reasoning model that consumes tokens for its thinking chain before producing output. Also falls back to `reasoning_content` if `content` is empty.
